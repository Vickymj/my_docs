## 1. What is UML?
UML (Unified Modeling Language) is a standardized way to visualize system design using diagrams.

## 2. Why is UML used?
- To visualize system structure
- To improve communication
- To design systems before coding

## 3. What is a Class Diagram?
A diagram that represents classes, attributes, methods, and relationships.

## 4. What is a Class?
A blueprint for creating objects.

## 5. What is an Object?
An instance of a class.

## 6. What are the main parts of a class diagram?
- Class Name
- Attributes
- Methods

## 7. What is Association?
A relationship where one class uses another.

## 8. What is Directed Association?
A one-way association.

## 9. What is Aggregation?
A weak "has-a" relationship (independent lifecycle).

## 10. What is Composition?
A strong "has-a" relationship (dependent lifecycle).

## 11. Difference between Aggregation and Composition?
- Aggregation: Weak ownership
- Composition: Strong ownership

## 12. What is Generalization?
Represents inheritance (IS-A relationship).

## 13. What is Realization?
A class implements an interface.

## 14. What is Dependency?
A temporary "uses-a" relationship.

## 15. What is Multiplicity?
Defines number of instances:
- 1 → one
- * → many
- 1..* → one or more
- 0..1 → optional

## 16. Difference between Association and Dependency?
- Association: Stronger, long-term
- Dependency: Temporary usage

## 17. What is an Interface in UML?
A contract that defines methods without implementation.

## 18. Can a class implement multiple interfaces?
Yes, and it's shown with dashed arrows in UML.

## 19. What is abstraction?
Hiding implementation and showing only essential details.

## 20. What is encapsulation?
Binding data and methods together with access control.

## 21. What is inheritance?
A class derives properties from another class.

## 22. What is polymorphism?
One interface, many implementations.

## 23. What is a Use Case Diagram?
Represents system interactions with users.

## 24. What is a Sequence Diagram?
Shows interaction between objects over time.

## 25. What is an Activity Diagram?
Represents workflow or process flow.

## 26. Difference between Class Diagram and ER Diagram?
- UML: System design
- ER: Database design

## 27. What is 1:1 relationship?
One object relates to one object.

## 28. What is 1:N relationship?
One object relates to many objects.

## 29. What is N:M relationship?
Many objects relate to many objects.

## 30. How do you represent inheritance in UML?
Using a solid line with a hollow triangle.

## 31. How do you represent aggregation?
Using a hollow diamond.

## 32. How do you represent composition?
Using a filled diamond.

## 33. How do you represent dependency?
Using a dashed arrow.

## 34. What is a system boundary?
Defines system scope in UML diagrams.

## 35. What is a stereotype?
Adds extra meaning (e.g., `<<interface>>`).

## 36. What is an abstract class?
A class that cannot be instantiated.

## 37. How is an abstract class shown in UML?
Using italics or `<<abstract>>`.

## 38. What is coupling?
Degree of dependency between classes.

## 39. What is cohesion?
How well class responsibilities are focused.

## 40. Why is UML important in interviews?
- Shows design thinking
- Helps explain architecture
- Required in system design rounds

## 41. Example: Library System
- Classes: Book, Member, Librarian
- Relationships: Member borrows Book

## 42. Example: E-commerce System
- Classes: Product, Order, Customer
- Relationships: Customer places Orders

## 43. How do you represent one-to-many?
Using 1 → * multiplicity.

## 44. How do you represent many-to-many?
Using * ↔ * relationship.

## 45. What is dependency injection in UML?
A class receives dependencies instead of creating them.

## 46. How do you represent interfaces?
Using `<<interface>>` and dashed arrows.

## 47. What is the role of UML in Agile?
Used for quick design and communication.

## 48. Can UML be used in coding?
Yes, it helps plan before implementation.

## 49. What is a package diagram?
Represents grouping of related classes.

## 50. What is a component diagram?
Represents system components and their dependencies.
